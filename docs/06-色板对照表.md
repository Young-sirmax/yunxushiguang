## 六、不在 WXSS 里的例外（为什么还看得到硬编码）

| 位置 | 为什么不能用令牌 | 怎么办 |
|---|---|---|
| `app.json` / 页面 `.json` 的 `navigationBarBackgroundColor`、`tabBar` 色 | 小程序配置文件不支持 CSS 变量 | 直接写十六进制，值见本表「品牌主色」（`#22B07D`） |
| `wx.showModal({ confirmColor })` 等原生接口 | 颜色参数走原生层，不在 WXSS 层叠里，传 `var(--x)` 会被当非法值忽略 | 统一走 `miniprogram/utils/nativeColors.js` |
| `utils/theme.js` 的 `TOKENS` / `TYPE_THEME` | canvas 读不到 CSS 变量 | 该文件是 canvas 侧唯一来源，改色必须与 `styles/theme.wxss` 同步 |
| `utils/avatar.js` 的字母头像底色池 | 值以行内 `style="background:…"` 输出，CSS 变量可正常解析 | 直接写 `var(--…)`，随主色自动跟随 |
| 阴影 / 遮罩里的墨色、黑色 rgba | 阴影是「明度叠加」而非品牌色，跟主色走会串味 | 收敛到 `styles/theme.wxss` 的效果令牌，页面不再自己拼 |
