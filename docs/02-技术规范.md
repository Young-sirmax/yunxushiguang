# 技术规范（扫描现有代码得出，非新造）

> 扫描范围：`cloudfunctions/` 全部 21 个云函数 + `miniprogram/` 现有页面
> 基准文件：`cloudfunctions/review/index.js`、`cloudfunctions/user/index.js`（风格最统一）

## 一、云函数基本写法

```js
const cloud = require('wx-server-sdk');
cloud.init({ env: 'cloud1-d0gvvc41c5a9dab3f' });
const db = cloud.database();
const _ = db.command;

exports.main = async (event, context) => { /* ... */ };
```

- 每个云函数目录下必须有 `package.json`，依赖固定 `"wx-server-sdk": "latest"`，`"main": "index.js"`。
- 环境 ID 一律硬编码 `cloud1-d0gvvc41c5a9dab3f`。
- 顶部写文件用途注释；关键分支写中文注释说明「为什么」而不是「做了什么」。

## 二、返回格式（全部云函数一致）

| 场景 | 返回 |
|---|---|
| 成功（有数据） | `{ code: 0, data: ... }` |
| 成功（列表） | `{ code: 0, data: [...], total: n }` |
| 成功（有提示） | `{ code: 0, data: ..., msg: '提交成功' }` |
| 失败 | `{ code: -1, msg: '中文可读原因' }` |

- **不抛异常给前端**：业务错误一律 `return { code: -1, msg }`。
- `msg` 面向用户，必须是中文人话，不出现英文/错误码。

## 三、错误处理

- 数据库写操作包 `try/catch`，`catch` 里 `console.error('[模块名] 描述:', err)` 后返回 `{ code: -1, msg: '操作失败，请稍后重试' }`。
- 日志统一前缀 `[模块名]`（如 `[review]`、`[user]`），便于云开发控制台按关键字检索。
- 依赖外部接口（`msgSecCheck` / `imgSecCheck`）时**降级放行**并记日志，不允许因安全检查服务异常卡死用户流程。

## 四、登录态与用户身份

- openid 来源：`cloud.getWXContext().OPENID`，**不接受客户端传 openid**。
- 用户文档：`db.collection('user').where({ _openid: openid }).limit(1).get()`，取 `data[0]`。
- 需要用户主键时用 `user._id`（本模块 `userId` 存 `_id`，不存 openid）。
- 未登录（拿不到 openid）直接 `return { code: -1, msg: '请先登录' }`。

## 五、权限判断（既有三套，新增模块按需复用）

| 机制 | 位置 | 判定方式 |
|---|---|---|
| 平台管理员 | `cloudfunctions/admin` | 管理密码绑定后写 `user.isAdmin = true` |
| 批量上架白名单 | `cloudfunctions/adminBatch`、`config` | `config` 集合 `key:'app'` 记录的 `admin_openids` 数组包含当前 openid |
| 维护模式 | `commodity` / `user` / `review` | `config` 记录 `maintenance === true` 时拒绝写操作 |

- 维护模式读取写法照抄 `user/index.js` 的 `isMaintenanceOn()`：**直连读 config 集合**，不跨云函数调用；读失败按「未开启维护」处理。
- 图书角新增的空间级权限（`space.managers`）是**第四条独立权限线**，与上面三套互不覆盖。

## 六、分页与查询

- 单页上限常量 `MAX_PAGE_SIZE = 20`（`commodity` / `adminBatch` 同款）。
- 统一 `page` / `pageSize` 归一化：`Math.max(1, parseInt(x, 10) || 1)`、`Math.min(MAX_PAGE_SIZE, Math.max(1, ...))`。
- 列表返回 `{ data/list, total }`，`total` 用 `.count()` 单独查，不用 `.get()` 的长度冒充。
- **禁止无 `limit()` 的全量查询**（唯一例外：明确知道数据量 ≤ 1 的 `where({key:'app'}).limit(1)`）。

## 七、时间与字段命名

- 写入时间统一 `db.serverDate()`，不接受客户端时间。
- 命名沿用各集合的历史约定：
  - `commodity` / `user`：`createTime` / `updateTime`
  - `review`：`created_at`
  - **图书角新集合（space / book / book_comment / exchange_log / op_log）：`createdAt` / `updatedAt`**（从新从简，不再扩散历史命名）

## 八、内容安全

- 文本：`cloud.openapi.security.msgSecCheck({ content })`，`errCode === 0` 视为通过。
- 图片：先 `cloud.downloadFile({ fileID })` 拿 buffer，再 `imgSecCheck({ media: { contentType: 'image/jpeg', value: buffer } })`。
- 两者**均为降级放行**（接口异常时不拦截，记日志）。
- 平台自定的引流/违规交易词（加微信、刷单、代写…）`msgSecCheck` 不拦，必须走 `config.sensitiveWords` 本地词表。

## 九、本项目禁止的写法

1. 禁止引入新框架、新依赖（不装 npm 包，不用 TypeScript/ESM 语法，云函数一律 CommonJS）。
2. 禁止在云函数里 `throw` 业务异常，禁止返回非 `{code,msg/data}` 结构。
3. 禁止信任客户端传入的 `openid` / `userId` / `nickname` / 时间戳。
4. 禁止物理删除数据库文档（`op_log` 归档除外），一律 `status` 软删除。
5. 禁止无 `limit` 的全量查询、禁止 `skip` 深度分页超过 20 页仍不分批。
6. 禁止把 `config.sensitiveWords`、`admin_openids` 下发给客户端。
7. 禁止跨云函数调用（云函数之间不做 `callFunction`）。
8. 禁止在小程序端直接读写数据库（所有集合权限均为「仅管理端可读写」，前端只能走云函数）。
9. 禁止把手写敏感配置（密码、密钥）写进前端代码。
10. 禁止在页面 / 组件里写颜色硬编码（十六进制、裸 `rgb()`/`rgba()`），一律走
    `miniprogram/styles/theme.wxss` 的令牌。

> 已把这批变量整体换成新色板并迁到 `styles/theme.wxss`，原条文的保护对象（避免
> 单点改色导致全站不一致）现在由第 10 条 + 令牌单一来源来保证，故改写为第 10 条。
