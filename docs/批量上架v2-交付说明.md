## 二、⚠️ 与既有约定冲突 / 需你决策的事项

指令要求「改造中若与既有约定冲突，以既有约定为准，并在交付说明里单列出来」。以下 8 项请过目。

### A. 「新建集合」超出指令范围：多了 `batch_invite`

指令 4.1 只给了 `batch_admin` 的结构，但 4.2 方式 A 要求「token 5 分钟有效、一次性」——
**一次性必须落库**（要记 `used`），而 `batch_admin.status` 的枚举只有 `active|revoked`，塞不下。
故新建 `batch_invite` 集合：`{ _id, token, grantedBy, note, used, usedBy, usedAt, expireAt, createdAt }`。

**替代方案**（若你不接受新集合）：把 token 塞进 `batch_admin` 并扩展 `status` 枚举加 `pending`。
我选新建，因为它不污染 `batch_admin` 的语义、且过期 token 可整表清理。

### B. `batch_admin` 结构加了 3 个字段

指令 4.1 给的是 `{ _id, openid, nickName, avatarUrl, grantedBy, grantTime, status, note }`。
指令第 8 节又要求「授予与回收均留审计」，但原结构**没有回收侧的字段**。故补：
`revokedBy`、`revokeTime`、`grantedVia`（`manual` | `invite`，区分方式 A / 方式 B）。

### C. 极简模式拿不到图片文件名 → 5.2 规则 1 实际不生效

**这是指令内部的一个技术前提不成立。**

- 5.2 规则 1 要求「图片文件名是可读文本 → 直接用文件名」；
- 但极简模式走 `wx.chooseMedia`（相册/拍摄），它返回的 `tempFilePath` 形如 `wxfile://tmp_xxx.jpg`，
  **不包含相册里的原始文件名**；
- 能拿到 `name` 的只有 `wx.chooseMessageFile` —— 而那正是第 2 节要废掉的「文件传输助手」路径。

**我的处理**：规则 1 照实现（行数据里若带了 `fileName` 就用），但不指望触发；
日常一律走规则 2（`闲置 MMDD N/M`）。**未擅自改规则，也未把文件名硬凑出来。**

### D. 标题里的日期做了时区修正

云函数运行时时区为 UTC，`new Date().getMonth()` 在北京时间 08:00 前会算出**前一天**，
导致 `闲置 MMDD` 的日期错一天。故新增 `beijingMMDD()` 显式 +8 再取 UTC 字段。

> 顺带提一句：`cloudfunctions/user/index.js` 里注册用户时算 `auctionMonth` 用的是同样的裸 `new Date()`，
> **存在同一个时区隐患**。不在本次范围，未改动，仅记录在此。

### E. `grantAdmin` 改用 `userId` 而不是 `openid`

指令 7 写「入参：目标 openid 或一次性邀请 token」，但 4.2 方式 B 的是「从 user 集合按昵称搜索」，
而 7 又要求 `listAdmins` **不返回完整 openid** —— 那客户端就拿不到可操作的句柄。
故：搜索接口返回 `user._id`，`grantAdmin` 收 `userId` 后**服务端反查 openid**；
`revokeAdmin` 收 `batch_admin._id`。**客户端全程不持有 openid**，与 4.3「白名单永不下发」口径一致。
（同时保留了直接传 `openid` 的入参，应付「手动输入 openid」的兜底场景。）

### F. 待上架页「全部上架」从 N 次串行改为 1 次 `publishBatch`

原实现是前端 `for` 循环逐条调 `publishDraft`（20 条 = 20 次云函数调用）。
既然指令 7 要求新增 `publishBatch`，就顺手把这里也切过去了。**行为对用户不变，调用次数从 N 降到 1。**

### G. `sensitiveWords` 的读取权限口径变了

原先是 `admin_openids` 白名单，现改为「超管名单（`super_admin_openids` 回退 `admin_openids`）」。
因為回退逻辑保证超管名单是 `admin_openids` 的超集，**存量环境下原有管理员仍可读**，行为兼容。

### H. 依赖 `wx.showModal` 的 `editable` 参数

「批量填充价格」用了 `wx.showModal({ editable: true })`，**需要基础库 ≥ 2.17.1**。
项目 `app.json` 未锁最低基础库，若线上有低版本用户，该功能会静默失效（弹窗无输入框）。
已在 `project.config.json` 之外无配置可改，**请你确认线上最低基础库版本**。

## 三、新集合初始化说明

### 3.1 创建两个集合

云开发控制台 → 数据库 → **新建集合**，依次建：

| 集合名 | 用途 |
|---|---|
| `batch_admin` | 批量上架授权名单 |
| `batch_invite` | 邀请卡一次性 token |

### 3.2 权限设置（**两个集合都要做**）

进入集合 → **权限设置** → 选 **「所有用户不可读写」**。

> 云函数以管理员身份访问数据库，**不受集合权限约束**；这样设可以让客户端无法直连，
> 所有读写强制走云函数，鉴权才有唯一收口。与既有 `user` / `commodity` / `config` 策略一致。

### 3.3 索引

| 集合 | 索引字段 | 类型 | 索引属性 |
|---|---|---|---|
| `batch_admin` | `openid` | 升序 | 非唯一 |
| `batch_invite` | `token` | 升序 | 非唯一 |

路径：集合详情 → **索引管理** → 新建索引 → 填字段与排序方向 → 确定（异步构建）。

### 3.4 超管 openid 写在哪

云开发控制台 → 数据库 → `config` 集合 → `key = "app"` 的记录 → 编辑 → 新增字段：

```
字段名：super_admin_openids
类型：  数组
值：    ["oXXXXXXXXXXXXXXXXXXXXXXXXXXX"]
```

**不填也可以**：该字段缺失或为空时，`isSuperAdmin` 自动回退到既有的 `admin_openids`。
所以存量环境**可以什么都不改**，先把 `adminBatch` 和 `config` 部署上去即可。

### 3.5 部署顺序

1. 建 `batch_admin`、`batch_invite` 集合 + 权限 + 索引；
2. 部署 `config`（云函数 → 右键 → **上传并部署：云端安装依赖**）；
3. 部署 `adminBatch`（同上，**必须选「云端安装依赖」**，它依赖 `adm-zip`）；
4. 小程序端上传体验版，用超管账号进「我的 → 批量上架 → 授权」自测。
