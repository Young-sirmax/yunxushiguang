## 一、本次上线需要你手动做的事（清单）

### 1. 重新部署云函数（必须）
微信开发者工具 → 右键对应目录 → **上传并部署：云端安装依赖**

| 云函数 | 本次改动 | 是否必须 |
|---|---|---|
| `commodity` | 技能类型、卡片字段精简、分页上限、发布限流、复制限流、维护模式、达人字段注入 | ✅ 必须 |
| `user` | 手机号/微信号字段、微信号唯一校验、达人入驻/撤销/审核、维护模式 | ✅ 必须 |
| `admin` | 用户列表返回手机号/微信号/达人状态 | ✅ 必须 |
| `favorite` | 收藏快照补 type / tradeStatus / exchange_want | ✅ 必须 |
| `category` | 分类展示顺序（书籍教材置前） | ✅ 必须 |
| `review` | **新增**：技能服务评价 | ✅ 必须（新） |
| `config` | **新增**：维护模式开关 | ✅ 必须（新） |
| `migrate` | **新增**：一次性数据迁移 | ✅ 必须（新） |

### 2. 创建新集合（必须）
云开发控制台 → 数据库 → 新建集合：

- `review` —— 技能服务评价
- `rate_limit` —— 联系方式复制限流计数（不存在时云函数会降级放行，但限流不生效）
- `config` —— 全局配置（维护模式）

### 3. 写入维护模式配置（必须）
在 `config` 集合新增一条记录（JSON）：

```json
{ "key": "app", "maintenance": false, "notice": "系统维护中，请稍后再试" }
```

### 4. 执行数据迁移（必须，见《数据迁移与索引.md》）

### 5. 小程序后台手动配置（建议）

| 事项 | 路径 | 建议值 / 说明 |
|---|---|---|
| 服务内容声明 · 用户隐私保护指引 | 小程序后台 → 设置 → 服务内容声明 | 声明并勾选：**相册（选择图片）**、**摄像头**、**头像（chooseAvatar）**、**上传文件**；否则选择图片可能被微信拦截 |
| 错误告警（脚本错误、接口失败） | 小程序后台 → 运维中心 → 监控告警 → 告警设置 | 开启「**脚本错误**」「**接口调用失败**」，阈值建议：**5 分钟内错误数 ≥ 10** 即告警，通知方式勾选微信 |

| 内容安全接口 | 小程序后台 → 开发 → 开发设置 | 确认已开通 `security.msgSecCheck` / `security.imgSecCheck` 权限（发布审核依赖） |

## 二、云开发控制台：监控与数据看板在哪看

| 想看什么 | 路径 |
|---|---|
| **QPS / 调用次数 / 错误率**（云函数） | 云开发控制台 → 云函数 → 选择函数 → **监控** |
| **云函数日志**（含 `console.error` 与限流拦截） | 云开发控制台 → 云函数 → 选择函数 → **日志**（可按时间/关键字检索） |
| **慢查询 / 数据库性能** | 云开发控制台 → 数据库 → 集合 → **索引管理**（未建索引的查询会随数据量线性变慢）；另见 → **统计/监控** |
| **存储用量 / 流量** | 云开发控制台 → **存储** → 用量统计；总览页可看 **资源使用情况**（CDN 流量、存储、数据库读写次数） |
| **数据库读写次数** | 云开发控制台 → 数据库 → **数据库监控** |
| 小程序端体验数据 | 小程序后台 → **运维中心 → 性能监控 / 实时日志** |

**关键告警阈值建议（用户量增长后）**
- 云函数单函数错误率 ≥ 3% → 排查日志中的 `[commodity]` / `[user]` / `[review]` 前缀
- 数据库单集合查询耗时 P99 ≥ 300ms → 检查《数据迁移与索引.md》中的索引是否缺失
- 存储 CDN 流量突增 → 检查是否有用户上传超大图（客户端已压缩到 ≤500KB，若仍异常说明走了老版本客户端）

## 三、紧急预案：开启「维护模式」

**效果**：全站进入只读状态——**可以浏览列表与详情**；发布、编辑、标记交易状态、评价、达人入驻等**写操作**会被云函数拒绝并提示「系统维护中，请稍后再试」。首页顶部会显示维护横幅。

**操作步骤（30 秒完成）**
1. 打开 **云开发控制台 → 数据库 → `config` 集合**；
2. 找到 `key = "app"` 的记录，点「编辑」；
3. 把 `maintenance` 改为 `true`（可同时修改 `notice` 文案）；
4. 保存。**无需重新部署，最长 5 分钟内全量生效**（客户端有 5 分钟配置缓存；如需立即生效，可让用户重启小程序）。

**恢复**：同路径把 `maintenance` 改回 `false`。

**注意**
- 若 `config` 集合或记录不存在，系统按「未开启维护」处理（不会误伤）。
- 维护模式**不影响历史数据**，关闭后一切照常。

## 四、达人（技能服务）审核操作方式

当前策略：**提交即自动通过**（你无需任何后台）。如需干预，有两个入口：

**方式一：小程序内操作（推荐，无需数据库）**
1. 「我的」→ 输入管理密码进入**管理员后台**；
2. 顶部切到 **数据管理 → 用户数据**；
3. 搜索该用户 → 点击 **「设为达人 / 撤销达人」**。

**方式二：云控制台手动改**
`user` 集合中把目标用户 `expert_status` 改为 `approved`（通过）/ `rejected`（驳回，可同时写 `expert_reject_reason`）/ `none`（撤销）。

**预留的人工审核接口**（若将来想改成先审后发）
- 云函数 `user`：`expertAudit(userId, result, reason)`，`result ∈ approved|rejected|none`；
- 把 `cloudfunctions/user/index.js` 中 `expertApply` 的 `expert_status: 'approved'` 改为 `'pending'`，即切换为「提交后待审」。

## 五、常见问题排查

| 现象 | 排查方向 |
|---|---|
| 首页空无一物 | 是否所有信息都处于 `pendingReview`（未审核）；或维护模式误开 |
| 发布提示「发布太频繁」 | 服务端限流：1 分钟 1 条、1 天 10 条（正常防刷，非故障） |
| 复制联系方式提示「操作过于频繁」 | 复制限流：同一用户每分钟最多 20 次 |
| 发布技能服务提示「请先完成技能达人入驻」 | 该账号 `expert_status !== 'approved'` |
| 图片不显示 | 检查云存储文件是否存在；列表只下发首图 `cover`，详情页才是完整图片数组 |
| 「我发布的信息」只显示 20 条 | 单页上限 20 条（防全量拉取），更早的信息建议先删除整理 |
| 接口报「系统维护中」 | `config.maintenance = true`，按第三节恢复 |

## 六、技能参考价区间配置（仅提示，不做强制定价）

「技能服务」发布页会在选择技能分类后，于报价输入框下方显示一行灰色提示：
**「该类目参考价：30-80 元/小时」**，仅作引导，**不校验、不拦截、不做任何标记**。

### 修改方式（不用改代码、不用重新部署）

云开发控制台 → 数据库 → `config` 集合 → `key = "app"` 的记录 → 增加/编辑字段 **`skill_price_ref`**：

```json
"skill_price_ref": {
  "家教辅导": { "min": 30, "max": 80, "unit": "per_hour" },
  "摄影修图": { "min": 20, "max": 50, "unit": "per_time" },
  "设计剪辑": { "min": 30, "max": 100, "unit": "per_time" },
  "编程开发": { "min": 50, "max": 150, "unit": "per_time" },
  "乐器教学": { "min": 40, "max": 100, "unit": "per_hour" },
  "运动陪练": { "min": 20, "max": 60, "unit": "per_hour" },
  "跑腿代办": { "min": 5, "max": 20, "unit": "per_time" },
  "其他": { "min": 10, "max": 50, "unit": "per_time" }
}
```

- `unit` 取值：`per_hour`（显示"元/小时"）、`per_time`（显示"元/次"）；
- 只需写你想覆盖的类目，未写的类目自动使用**前端默认表**兜底（见 `miniprogram/utils/expert.js` 的 `SKILL_PRICE_REF`）；
- 保存后最长 5 分钟生效（客户端有配置缓存，退出小程序重进即可立即生效）。

### 后续观察用（当前未启用）

`miniprogram/utils/expert.js` 已预留 `isPriceOutOfRef(price, ref, threshold = 0.5)`：
判断报价是否超出参考区间 50% 以上（高于上限 1.5 倍或低于下限 0.5 倍）。
**目前该函数不参与任何展示与校验**（按需求"先观察，不做 judge"）；若将来要在卡片/详情上打标提醒，直接调用它即可。
