> 配套云函数：`migrate`（仅管理员可调用）
> 云开发环境：`cloud1-d0gvvc41c5a9dab3f`

## 一、新增索引清单（必须手动创建）

微信云开发的索引需在控制台创建：**云开发控制台 → 数据库 → 选择集合 → 索引管理 → 添加索引**。
索引对**存量库和新库都需要创建**（新库指今后新建的同类环境）。

| 集合 | 索引字段 | 类型 | 用途 |
|---|---|---|---|
| `commodity` | `status` | 升序 | 公开列表/搜索固定过滤 `status = 'onSale'`（最高频） |
| `commodity` | `type` | 升序 | 类型筛选（闲置/求购/易物/技能） |
| `commodity` | `categoryId` | 升序 | 分类筛选 |
| `commodity` | `_openid` | 升序 | 「我发布的信息」按发布者查询 |
| `commodity` | `createTime` | 降序 | 列表排序（所有列表都按它排序） |
| `commodity` | `status + createTime` | 组合（status 升序, createTime 降序） | **推荐**：公开列表的主查询路径 |
| `commodity` | `type + createTime` | 组合（type 升序, createTime 降序） | **推荐**：类型筛选列表 |
| `commodity` | `_openid + createTime` | 组合（_openid 升序, createTime 降序） | **推荐**：我的发布 + 发布频率限制查询 |
| `user` | `_openid` | 升序 | 几乎所有用户查询（唯一标识） |
| `user` | `wechat_id` | 升序 | 微信号唯一性校验 |
| `user` | `expert_status` | 升序 | 达人筛选/统计 |
| `user` | `wechat_id + _openid` | 组合 | **推荐**：微信号唯一性校验（排除自己） |
| `review` | `target_id + created_at` | 组合（target_id 升序, created_at 降序） | **推荐**：达人主页/我收到的评价 |
| `review` | `rater_id + post_id` | 组合 | **推荐**：同一帖子只能评价一次的校验 |
| `rate_limit` | `_openid + key + time` | 组合 | **推荐**：联系方式复制限流计数 |
| `favorites` | `_openid + createTime` | 组合 | 我的收藏列表 |
| `config` | `key` | 升序 | 维护模式配置读取 |

> 说明：`commodity` 的 `createdAt` 在本项目中实际字段名为 **`createTime`**（云函数写入 `db.serverDate()`），索引请按 `createTime` 建。

## 二、新增集合

| 集合 | 说明 | 是否必须 |
|---|---|---|
| `review` | 技能服务评价：`rater_id` / `target_id` / `post_id` / `rating(1-5)` / `comment` / `created_at` | ✅ |
| `rate_limit` | 复制联系方式限流计数：`_openid` / `key` / `time` | ✅（缺失时限流降级放行） |
| `config` | 全局配置：`{ key:"app", maintenance:false, notice:"" }` | ✅ |

## 三、数据迁移步骤（一次性）

### 迁移内容
1. `user.contact` → `phone`（手机号格式）或 `wechat_id`（微信号格式）；无法判定时留在 `phone` 兜底，并移除 `contact`
2. `user` 补齐 `wechat_id` / `phone` 字段
3. `user` 补齐技能达人字段（`expert_status` 默认 `none`、`rating_sum`/`rating_count` 默认 0）
4. `commodity.type` 缺失补 `sell`
5. `commodity.tradeStatus` 缺失补 `open`（历史 `status='sold'` 记为 `completed`）
6. `commodity.sellerContact` → `sellerPhone` 快照，并移除 `sellerContact`

### 执行步骤

```text
0) 先备份！云开发控制台 → 数据库 → 选中集合 → 导出（user / commodity 各导出一次）
1) 部署云函数：migrate、user、commodity、admin、favorite、category、review、config
2) 创建集合：review / rate_limit / config，并写入 config 记录
3) 建立第一节中的索引
4) 预演（不写库，先看日志确认逻辑）：
     在开发者工具 → 云函数 migrate → 云端测试，传入：
     { "action": "status" }                                   ← 查看各步骤剩余待迁移数量
     { "action": "run", "target": "all", "dryRun": true }     ← 预演一批（看日志）
5) 正式执行（每批默认 50 条，最多 100）：
     { "action": "run", "target": "all" }
   反复调用，直到 { "action": "status" } 中所有 remaining 均为 0
6) 抽查：user 集合随机几条确认已有 wechat_id；commodity 确认 type/tradeStatus 已补齐
```

### 可选的精确执行
`target` 支持单步：`users` / `commodity` / `all`，或具体步骤名：
`userContact`、`userFields`（步骤2，脚本内名 `userWechatField`）、`userExpertField`、`commodityType`、`commodityTradeStatus`、`commoditySellerContact`。

### 注意事项
- 迁移**不可逆**，务必先导出备份；
- 迁移期间用户可正常使用，但建议低峰期执行；
- `contact` 若为历史遗留的非法格式，会被放入 `phone`（仅作兜底复制来源，不在任何页面展示），用户可在「个人信息」中清空或修正；
- 迁移完成后，`user.contact` 字段在代码中已不再使用（仅保留旧客户端写入的兼容映射）。

## 四、存量库 vs 新库

| 场景 | 需要做什么 |
|---|---|
| **存量库**（当前线上环境） | 按第一~三节：建索引 → 建集合 → 写 config → 跑迁移 |
| **新库**（今后新开的环境） | 仅需：建集合（含 review/rate_limit/config）→ 建索引 → 写 config 记录；**无需迁移**（新库无历史数据） |
