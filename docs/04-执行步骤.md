## 部署清单（每步都要核）

| 云函数 | 何时必须部署 |
|---|---|
| `config` | 指令 1 后（`sensitiveWords` 支持），否则敏感词接口不存在 |
| `bookcorner` | 指令 2 后 |
| `commentReview` | 指令 3 后、指令 4 前 |

## 每个功能完成后的固定动作

1. 静态自查（`node --check` 语法 + 逐条对照 `docs/01-开发需求.md`）。
2. 追加三行复盘到 `docs/05-经验日志.md`，并在对话里单独输出这三行，供用户过目。
3. git 提交一次（一条指令一个 commit），提交信息写清「做了什么 + 影响面」。
4. 独立视角审查（Kimi 第二遍审查指令）：只报问题、不改代码，按 🔴/🟡/🔵 分级 + 文件行号。
