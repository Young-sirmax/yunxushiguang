## 2026-09-18 · 指令 2（bookcorner 云函数）

- 坑：Kimi 指令里 `review/addComment` 要求「返回 { status, message }」，但本项目云函数统一返回 `{ code, msg, data }`，两套口径会打架。
- 解决：以项目既有规范为准，返回 `{ code:0, data:{ status }, msg:'留言已提交，将在审核后展示' }`，并在文件头注释里写明取舍。
- 下次指令补充：涉及返回结构的指令，请直接写明「以现有云函数规范为准」或给出完整示例，避免二选一。

## 2026-09-18 · 指令 2/6（留言分页）

- 坑：原指令只给了 4 个 action（getBooks / getBookDetail / addComment / addExchange），但指令 6 要求留言「分页 20 条」，缺少列表接口。
- 解决：新增 `getComments`（已通过、加精置顶、时间正序、分页），并在 docs/01 与代码注释里标注这是为满足指令 6 增补的接口。
- 下次指令补充：写「页面需要什么交互」时，顺手把「需要哪些接口」列出来，避免执行者自行补接口导致与预期不符。

## 2026-09-18 · 指令 1/5（分区命名）

- 坑：运营方案里 A 区=教材流转、B 区=馆内阅览，而开发指令第 5 条写成「A区 · 馆内阅览」「B区 · 教材流转」，两份文档自相矛盾。
- 解决：以数据层与运营方案为准（A=教材流转可外带，B=馆内阅览不外带），并把这条写进 `docs/01-开发需求.md` 与 `miniprogram/utils/bookcorner.js` 注释，页面文案统一从 `ZONES` 常量取。
- 下次指令补充：A/B、状态枚举这类命名，请在指令里给一张「枚举值 → 业务含义」对照表，只写一次。
